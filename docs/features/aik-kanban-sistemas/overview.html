AIK — front de sistemas em kanban hierárquico

Um jeito novo de olhar o OpenHands: cada sistema é um workspace, o trabalho dele é um quadro, e o agente executa direto do card.

aik.zadotec.com.br 4 releases 11 sprints, 5 ondas

O problema

❌
A tela de "quadros" é uma lista. Não existe baia nenhuma pra ver o sistema como kanban.
❌
Só um nível aparece de verdade. Sub-tarefas ficam em modal empurrado dentro de outro modal — dá a sensação de "separado e confuso".
❌
Executar quase nunca está disponível. O botão fica desabilitado na maioria dos cards, e não existe conversa dentro do próprio quadro.

Essas três queixas foram registradas pelo próprio usuário do produto, direto no quadro que ele estava tentando usar.

O que vai ser entregue

Hierarquia sem modal empilhado

Sistema → Fase → Tarefa, cada nível com sua própria tela e um breadcrumb navegável. Fase é um container — nunca executa sozinha, sempre reflete o estado real das tarefas dentro dela.

Executar sem pré-condição escondida

Toda tarefa com instrução pro agente e backend de pé mostra o botão Executar. Se já existe um agente trabalhando naquele sistema, o botão explica por que está esperando — nunca some sem explicação.

Revisão humana obrigatória

O agente nunca marca uma tarefa como concluída sozinho — ele entrega, e um humano aprova ou devolve com feedback, na mesma conversa.

Conversa embutida, em qualquer nível

Um painel lateral com o chat do sistema, acessível de qualquer tela — reaproveitando o motor de conversa que o OpenHands já tem, maduro e testado, sem reescrever nada.

Sistema = workspace

Um sistema no AIK é, literalmente, um workspace do OpenHands — local (uma pasta no disco) ou remoto (um repositório no OpenHands Cloud). É a mesma peça que o produto já usa hoje pra saber onde o agente trabalha; o AIK só organiza o trabalho dentro dela em fases e tarefas visíveis.

Riscos que vale a pena conhecer

Roteamento por endereço (Sprint 02). A forma como o site vai decidir "isto é o AIK, isto é o site atual" olhando só o endereço acessado nunca foi feita neste projeto antes. Por isso o próprio plano exige uma prova em navegador real antes de seguir, com um plano B pronto caso não funcione do primeiro jeito.

Um agente por vez, por sistema. Na primeira versão, cada sistema só roda um agente de cada vez — sem fila, sem múltiplas execuções simultâneas. Fica visível na tela quando isso acontece, nunca escondido.

O que fica de fora, por enquanto

  • Fila de execuções com posição e custo por tarefa
  • Um quarto nível de quadro (hoje o detalhe fino vira checklist dentro do card)
  • Substituir ou remover o site atual do OpenHands
  • Múltiplos usuários e permissões
  • Trazer automaticamente os quadros que já existem hoje pro formato novo
