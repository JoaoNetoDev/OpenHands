OpenHands Tray — Canvas na VPS ↔ Agent local

Binário Go + Wails3 que age como bridge nativo entre o Canvas hospedado na VPS e o agent-server local. Conexão WSS outbound (passa qualquer NAT), reverse-proxy HTTP ↔ WS, sidecar reusando o launcher existente.

Problema

Hoje, com o Canvas do OpenHands numa VPS e o usuário querendo que a execução aconteça na máquina local dele (atrás de NAT/firewall, sem expor portas), os caminhos informais são Tailscale, SSH reverso ou expor o agent-server da máquina local. Nenhum nativo, nenhum documentado, nenhum reverso.

O artefato openhands-tray-design.md na raiz do repo propõe o Tray. Esta doc-set (PRD/SPEC/TECH) é a revisão estruturada do mesmo, com três correções factuais em relação à base real e quatro questões em aberto para decisão antes de qualquer código.

Correções factuais aplicadas

1. Spawn do agent-server. O artefato prescreve agent-server serve --backend-only, mas esse comando não existe. O real é uvx --from openhands-agent-server==<ver> agent-server --host 127.0.0.1 --port <p> (dev-safe.mjs:434-540), ou — melhor — reusar dev-with-automation.mjs --backend-only que já orquestra tudo.

2. Auth. O artefato propõe um token Bearer estático. A base já tem um modelo melhor: session API key de 32 bytes (crypto.randomBytes), persistida em ~/.openhands/agent-canvas/session-api-key.txt, compartilhada entre agent-server e automation. Reaproveitar evita silo novo de credenciais.

3. Fronteira de repositório. AGENTS.md é explícito: este repo é o frontend agent-canvas. O Tray (Go + Wails3) não pertence aqui — decidido no Sprint 01 que vai para um repo irmão do software-agent-sdk (nome de trabalho JoaoNetoDev/openhands-tray). Esta doc-set fica aqui porque é planning, não código.

Bônus. O wrapper electron/main.mjs (785 linhas) já implementa um desktop wrapper — para o caso mesma-máquina. Decidido no Sprint 01: o Tray substitui o Electron, mas de forma faseada (cross-host primeiro; remoção do Electron só com paridade). Ver PRD §8 RISCO-02.

Decisões tomadas (Sprint 01)

  • RISCO-01 — Código Go vai para repo irmão do software-agent-sdk (nome de trabalho JoaoNetoDev/openhands-tray). Nada de Go neste repo.
  • RISCO-02 — Electron é substituído, mas de forma faseada: o Tray cobre cross-host primeiro; a remoção do Electron vira sprint próprio (v1.0+) com checklist de paridade. Não se deleta infra testada antes da paridade.
  • RISCO-04 — Auth = Bearer estático no MVP (provisionado pela UI), Ed25519 no v1, mTLS descartado. A session key local é segredo separado que nunca cruza o fio.
  • QUESTÃO-01 — Endpoint WSS e gestão de tokens vivem na UI do Canvas: o instalador provisiona o bearer pela própria interface (tela de backends).

Resultado do spike (Sprint 01)

19/19 verificações passaram — VPS mock (WSS 8443) → Tray mock → agent-server mock (HTTP 18900, exige session key).

Refinamento que o spike destravou: o Tray injeta a session key local e descarta a que vier do cliente; o handler /agent-tunnel no ingress.mjs é um servidor WS terminal (não passthrough).

Limitação (fechada no Sprint 02): o agent-server do spike era um mock Node; a fidelidade do /server_info real ficou para o Sprint 02, que rodou o uvx de verdade e repetiu a verificação — 6/6 contra o agent-server 1.46.0 real.
