# 2026-09-14

## Bug: `sonnet/<effort>` no provider ACP `claude-code` (ficha aprovada + corrigido)

Fluxo `/bugreview` completo: ficha → aprovação → SPEC → implementação → deploy
staged. Artigos em `docs/bugs/claude-acp-effort-model-not-found/`
(`FICHA.md`, `SPEC.md`).

**Causa raiz**: o SDK em runtime (`openhands-sdk==1.46.0`) não separa o id
combinado `<model>/<effort>` para o `claude-code`. O commit `21cfc40` do fork
corrigia **só um** dos dois caminhos (`_model_config_options`); o `_meta` da
criação de sessão (`build_session_model_meta`) continuava mandando o id cru.
O `codex` nunca sofreu disso porque tem `session_meta_key=None` e devolve `{}` —
foi por isso que o fix parcial passou batido.

**Dois desfechos, mesmo defeito**: o id literal faz o CLI responder 404
`model_not_found` (falha dura); quando não bate, o `resolveModelPreference` do
wrapper degrada para o modelo base e **descarta o effort** (placebo silencioso).
Este segundo modo só apareceu no tracer dinâmico (strace do JSON-RPC).

**Correção**: `690243e` no fork — novo `_model_id_for_session_meta` reaproveitando
`_model_config_options` (regra de split única) + teste de invariante garantindo que
nenhum carrier emita id combinado como modelo. 553 testes verdes.

**Deploy staged**: `OH_AGENT_SERVER_LOCAL_PATH=/opt/software-agent-sdk-fix` em
`/etc/default/openhands`. Restart pendente, **de propósito** — ver MEMORY.md.

**Lição de método**: o tracer estático convergiu na causa raiz mas subestimou o
segundo caminho ("confiança média"); verificar por execução do código instalado
(`_model_config_options` + `build_session_model_meta`) mostrou que o fix existente
era incompleto. Vale sempre executar a função, não só ler.

**Sobre a referência LionCodeLabs**: confirmou o princípio (effort é campo
separado, nunca sufixo de modelo) mas não trouxe arquitetura nova — usa Claude
Agent SDK nativo com `{ effort }`, e no ACP manda `reasoningEffort` como campo
próprio.
