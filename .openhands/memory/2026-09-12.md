## The three bugs the tests caught

1. **Session key leaked back to the VPS.** `filterResponseHeaders` in the Go
   proxy only stripped hop-by-hop headers, so an agent-server response echoing
   `x-session-api-key` handed the Tray's credential to the VPS — a direct
   violation of SPEC §4.4, which is the invariant the whole design rests on.
   Test: `TestForwardNeverEchoesSessionKey`.
2. **Envelope accepted malformed base64.** `Request.Validate()` never decoded
   the body, so corruption surfaced only at forward time.
3. **One route prefix can't cover the bootstrap** (found only against the *real*
   agent-server). `--agent-tunnel-route /api` looked right, but `/server_info`
   lives at the root, so it fell through to the local `/server_info`
   interception and the bootstrap died. Made the flag repeatable and moved
   tunnel matching ahead of that interception.

Bug 3 is the argument for the real-server stage: the mock never exercised
`/server_info` at the root, so it passed 9/9 while the real topology was broken.

## Verification method worth reusing

Two-stage cross-language interop with a real Go binary against the real Node
handler:

- Stage 1, mock agent-server: lets you *inspect* the credential that arrives
  (echo it in a header/body) — 9/9.
- Stage 2, real agent-server 1.46.0 on :18000: proves auth actually works
  (`/api/settings` 401 direct → 200 through the tunnel) — 6/6.

Getting the real agent-server's key: it is **not** on disk here. The running
process has it in `OH_SESSION_API_KEYS_0`; read it from
`/proc/<pid>/environ` rather than printing it. Harnesses lived in
`/tmp/tray-e2e/` and `/tmp/tray-real/`, both deleted at sprint end.

# Sprint 03 — a UI de bandeja (Wails v3)

## O que foi entregue

`/opt/openhands-tray` commit **`68ce275`** em `main` (1 commit à frente do
`origin/main`, **não enviado**). O binário agora abre a **janela de
configuração** e mantém **ícone + menu na bandeja**. Docs: commit **`9d92846`**

`sprint/openhands-tray-02`, que voltou para `47006a4`; nada foi enviado).

## A decisão de arquitetura que importa

**Um ciclo de vida, dois frontends.** O `main.go` do Sprint 02 tinha a própria
sequência de startup. Isso foi movido para
`internal/desktop/controller.go` e os dois modos passaram a dirigi-lo:

- sem flags → `desktop.Run()` (GUI: controller + Service Wails)
- qualquer flag de conexão, ou `-headless` → `runHeadless()` + `Controller.Wait()`

Duplicar teria divergido na primeira correção. `Wait()` existe justamente para
o CLI não reimplementar o wiring.

## Erros que custaram tempo

1. **`Call.ByName` vs `Call.ByID`.** Os bindings gerados usam ID numérico; o JS
   puro (sem npm) usava o nome. A chave de registro é
   `fmt.Sprintf("%s.%s.%s", pkgPath, typeName, methodName)` (lido em
   `wails/v3/pkg/application/bindings.go`), então o nome totalmente qualificado
   é válido. Travado pelo teste `TestFrontendServiceNameMatchesGoBindings`, que
   lê o `main.js` e compara com `reflect.TypeOf(Service{})` — é a única string
   que quebra a janela inteira silenciosamente.
2. **A janela não cabia.** 560×660 para ~780 px de conteúdo: Salvar/Iniciar
   ficavam **abaixo da dobra** e a janela parecia quebrada. Achado medindo
   pixels, não lendo CSS: contagem da cor accent `#6366F1` deu **100 px** (só o
   checkbox) → **3350 px** depois de 580×800 + espaçamento menor.
3. **`CGO_ENABLED := 0` estava exportado no Makefile antigo.** Quebrava a GUI
   (que linka GTK/WebKit via cgo) e **já quebrava o `make race`**
   (`-race requires cgo`). `make vet` agora roda as duas configs porque um erro
   só-da-GUI (`undefined: pointer` dentro do Wails) só aparece com cgo ligado.
4. **`Service.SetNotifier(func(Status))` era método bindado** recebendo função —
   não marshalável do JS e superfície inútil. Removido; o notifier é registrado
   no controller a partir do `app.go`.

## Duas builds, por necessidade

A GUI não é cross-compilável. Então: `make build` (GUI, host, cgo) e
`make build-headless` (estática, 5 plataformas). Tags `gui` / `!gui`.

## Verificação

`make fmt-check`, `make vet`, `make test`, `make race` verdes; GUI 12M dinâmica,
headless 6.4M estática; `make release` 5/5. GUI rodou sob Xvfb, serviu `/`,
`/style.css`, `/main.js`; screenshot com **0 px** da cor de erro `#F87171` — que
é a evidência de que os bindings JS→Go responderam, porque o primeiro paint
chama `GetConfig` e `Status` e qualquer falha ali desenha o banner vermelho.
