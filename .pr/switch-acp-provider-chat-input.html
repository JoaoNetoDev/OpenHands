ACP provider switch v2 — persistent button in the chat input bar

Branch feat/switch-acp-provider-chat-input · based on sprint/openhands-tray-03 (d809785, after merging v1) · PR opens against sprint/openhands-tray-03 on JoaoNetoDev/OpenHands.

Supersedes v1 (banner-only) for happy-path discovery

v1 (feat/switch-acp-provider-on-error, merged into sprint/openhands-tray-03 as d809785) added a "Switch provider" button inside the error banner — visible only when the conversation is in a non-RUNNING error state. In practice, users hit acp_server === null on the wire and never see the banner offer. v2 keeps the banner recovery path but also adds an always-visible button in the chat input row, so the user can fork to a different ACP provider on any healthy ACP conversation — not only on the error banner.

v1 doc: switch-acp-provider.html.

1Motivation

The user wanted a way to "create a branch from a conversation" to keep going with possibly another ACP provider/model. Two recurring friction points made v1 unusable in practice:

  1. Gate is fragile — v1 requires acp_server to be stamped on SharedConversation by the agent-server; when that field is missing, the banner action never appears.
  2. Only visible on error — a user who just wants to try a different model on a healthy conversation has no affordance. The button only existed as a recovery from [-32603].

v2 fixes both: the new button lives in the chat input row, mirrors the slot ChangeAgentButton occupies (which is hidden in ACP context), and is visible any time the user has at least one OTHER ACP profile configured. The same useSwitchAcpProvider mutation does the heavy lifting.

Where it lands in the row

Before — cloud non-ACP shows the Code/Plan pill; ACP shows just the model picker.

＋ Code/Plan model · gpt-5.2 ↑

After — ACP context shows the new pill (icon ⇄ + active provider name) right next to the model picker.

＋ ⇄ Claude Code ▾ model · gpt-5.2 ↑

Click ⇄ Claude Code ▾ → popover lists every other configured ACP profile (OpenHands profiles filtered out, active profile excluded). Picking one runs useSwitchAcpProvider, which carries over workspace / repo / branch / plugins, sets parentConversationId, and navigates to the new id.

Notable Unlike v1, v2 does not gate on execution_status. The button is always available during a healthy conversation. Picking a profile from the popover creates a new conversation; the original keeps running and stays open in history — the user can flip back if they change their mind.

Manual smoke checklist

  1. Open any ACP conversation → input row should show ⇄ <current provider> ▾ pill.
  2. Click pill → popover lists every OTHER ACP profile (OpenHands profiles hidden, current hidden).
  3. Click a profile → new conversation starts with same workspace/repo, navigation lands on its id, original conversation stays in sidebar.
  4. If the agent-server returns acp_server === null, the pill still renders as long as agent_kind === 'acp' reaches the frontend — fallback inside canShowAcpProviderSwitch.

6Risks & follow-ups

  • Cloud parity — v2 stays local-only (cloud needs callCloudProxy wiring on the agent-profiles list endpoint before this can be enabled with backend.kind === "cloud"; tracks under #3730).
  • Row width — the pill is added before the model picker with no ref/overflow wiring. On narrow viewports the row may scroll/overflow. Acceptable for the primary desktop layout; revisit if mobile parity becomes a goal.
  • Tooltip on popover open — HeroUI StyledTooltip stays mounted while the popover is open; the popover overlays the tooltip with z-index from ContextMenu. No visual collision observed in local dev.
